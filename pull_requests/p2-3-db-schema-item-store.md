# P2.3 — DB schema & Item store

## Summary

Adds the project's **canonical database schema** (P2.3, type `DB`): defined once
as SQLAlchemy 2.0 models + a single Alembic migration in `backend-python/` and
**mirrored** as TypeORM entities (`synchronize:false`) in `backend-ts/`. A new
**cross-backend schema-parity check** in `contracts/` proves the Alembic head and
the TypeORM entities never drift on tables/columns/types/nullability (DA-8).

No HTTP endpoints change, so `/health` parity is untouched; the parity here is
**schema parity**.

## Changes (Large tier — 21 files; high-level by realm)

- **backend-python (canonical schema):** `app/models.py` declares all 14 tables —
  `accounts`, `transactions` (+ enrichment cols + unique `dedupe_key`, DA-19),
  `categories`, `budgets`, `loans`, `goals`, `holdings`, the budget precompute set
  (`budget_aggregates` + `budget_{bucket,category,monthly}_aggregates` +
  `recurring_charges`, covering **every** `/budget` field — DA-23), `plaid_items`
  (`access_token` `BYTEA` ciphertext — DA-12; `products text[]`; `status` enum),
  and `source_config`. One autogenerated migration (`f0bda61fcf45_*`); `env.py`
  imports the models so autogenerate/`alembic check` see them. Types per
  Appendix A: money `NUMERIC(14,2)`, percentages bare `NUMERIC` (DA-22),
  datetimes `timestamptz`, enums `TEXT`+`CHECK`, token `BYTEA`.
- **backend-ts (mirror):** `src/entities/entities.ts` mirrors every table/column/
  type via TypeORM decorators; `app.module.ts` registers `ALL_ENTITIES`,
  `synchronize:false`.
- **Schema-parity check (contracts):** both backends export a normalized
  `{table:{column:{type,nullable}}}` snapshot (`app/schema_export.py`,
  `src/entities/schema-export.ts` — hermetic, no DB); `src/schema.ts` diffs them;
  `test/schema.parity.test.ts` asserts byte-identical schemas + spot-checks
  money/percentage/bytea/timestamptz/text[]; `test/schema.unit.test.ts` covers
  the diff logic.
- **Tests & docs:** model/exporter tests both backends (≥80%); `STRUCTURE.md` +
  both backend READMEs updated; P2.3 marked `[x]`.

## Feature mapping

Foundation for **Wave 0.5 ingestion/precompute** (P3.*) and **Wave 1 view
endpoints** (P4.*) which read these tables; `plaid_items`/`source_config` back
the Wave-2 connections (P6.*). Enforces Rule #1 at the schema layer.
